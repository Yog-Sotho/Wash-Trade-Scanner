## 2025-02-15 - No-dependency Tab Groups & Accessible SPA Views
**Learning:** For lightweight single-page applications (SPAs) built with custom vanilla JS/CSS view toggling, simply changing styles (like `.hidden` or active states) leaves assistive tech blind to the active/inactive view state. By adding `role="tablist"` with `role="tab"` on the buttons and `role="tabpanel"` on the views, we explicitly link navigation triggers with content sections. Dynamically synchronizing the `aria-selected` attribute during tab interaction (via `tab.setAttribute("aria-selected", ...)` inside our event handlers) provides direct status updates to screen readers.
**Action:** Always structure custom tab components with explicit WAI-ARIA mapping (`role="tablist"`, `role="tab"`, `role="tabpanel"`, `aria-selected`, `aria-controls`) and synchronize state updates in the DOM click handlers, ensuring the interactive state is visible to screen readers.

## 2025-02-18 - Roving Tabindex and Arrow Key Navigation in Custom Tabs
**Learning:** In a WAI-ARIA custom tab group (`role="tablist"`), screen reader and keyboard-only users expect a roving tabindex pattern. Instead of having all tabs in the standard tab sequence, only the active tab should have `tabindex="0"`, and inactive tabs must have `tabindex="-1"`. Navigation between tabs is handled seamlessly via arrow keys (`ArrowRight`/`ArrowDown`/`ArrowLeft`/`ArrowUp`) and keyboard shortcuts (`Home`/`End`), which focus and select the targeted tab, updating their active classes, aria attributes, and roving tab indexes.
**Action:** Always implement a roving tabindex pattern for custom tab components alongside arrow key and home/end shortcut navigation to meet standard accessibility patterns and keyboard-only user expectations.

## 2026-08-07 - Accessible Data Visualization Rows & Dynamic Focus Tooltips
**Learning:** Standard static data-viz visual elements (like HTML bar-chart rows) are completely ignored by screen readers and keyboard users unless assigned `tabindex="0"` and an explicit `aria-label`. Moreover, tooltips bound solely to `mousemove` are inaccessible without mouse interactions. By extending tooltips to trigger on `focus`/`blur` events and computing the coordinate positions programmatically using `getBoundingClientRect()`, we provide an equivalent and highly delightful experience for keyboard-only and assistive technology users.
**Action:** For visual metrics or custom charts, always add `tabindex="0"` with dynamic aria labels, bind focus/blur event listeners to trigger tooltips relative to the focused element's position, and style visual feedback with `:focus-visible` outline rings.
